## 一、能直接装的开源工具

这几条是他实打实在用、而且给出优缺点评价的，不是随手转的链接。

### 1. Magpie —— 多渠道反代，解决 token 额度

- **地址**：https://github.com/yetone/magpie ｜ **中文文档**：https://github.com/yetone/magpie/blob/main/README.zh-CN.md
- **干什么**：把多个模型渠道/账号反代出来，统一成一个本地端点给各家 agent 用。
- **他的用法**：装好后注册 3～5 个 WorkBuddy 国际版账号直接反代。原话：「Workbuddy国际版的ds是不消耗token 的」「搞个3～5个账号 基本一天随便用了」。qoder 等其他渠道也能通过插件接入。
- **他自己列的优点**：比 cc switch 好用，装好可直接导入 ccs 配置无缝迁移；不同渠道的模型可聚合成路由组循环调用；支持多端同步供应商上游配置（s3 / webdev / github）；可映射本地路由地址；可共享给局域网；可跨 agent 框架共享 mcp 与 skill；内置过滤，给 AI 的是脱敏版。
- **他自己列的缺点**：更新过于频繁，一天更新几次。

### 2. Multica —— Agent 小队编排

- **地址**：https://github.com/multica-ai/multica
- **干什么**：跨智能体协作，多个 Agent 配合完成一个完整项目。
- **他的用法建议**：有商用版；开源版自己部署，推荐放服务器上 7×24 跑；支持多端协作、远程跑同一个项目。
- **他自己列的缺点**：非常消耗 token——执行 Agent 推荐 ds4.1f，主控 Agent 推荐 codex / Claude，前置建议先部署 Magpie 反代；速度比 ACP 协议和 sub-agent 慢很多。

### 3. wb-account-sync —— WorkBuddy 跨账号数据保留与同步

- **地址**：https://github.com/Guyungy/wb-account-sync
- **用途**：换账号/换版本时不丢历史数据，并持续同步。他自己只给了一句说明，没有展开用法。

### 4. SqlSeverToFeishu —— SQL Server 数据进多维表格

- **地址**：https://github.com/Guyungy/SqlSeverToFeishu
- **用途**：本地运行的 Web 工具，把 SQL Server 里的订单/业务数据同步（导入）到飞书多维表格，按业务主键自动去重。
- **适用场景**：客户已有 ERP/MES 数据库，不想走接口开发，先快速把数据搬进多维表格做验证。

### 5. humanizer-zh —— 中文去 AI 味

- **地址**：https://github.com/op7418/humanizer-zh
- **用途**：把 AI 生成的文字改得像人写的。他只在群里甩了链接，没写用法。

### 6. next-cloud-fde —— 团队 Skill 库

- **地址**：https://github.com/next-cloud-fde
- **用途**：团队沉淀的 Skill 仓库。他当时找同事要 GitHub 权限来拉这个库。

## 六、他反复讲的方法（不是文档，是聊天里的话）

这些没法「迁移」，但比文档更值钱，因为是判断标准。

### 带教总纲：从「能做出来」到「独立交付」

1. **客户的问题先接住，不要等解决完才回。** 哪怕还不知道怎么解，先回「收到，我看一下日志排查」。客户在意的首先是「有没有人在跟」。
2. **改完必须自己完整跑一遍核心流程**，并且给自己留测试时间。「修一个地方又带出新的问题」是他最不能接受的。
3. **先看日志和链路，少靠猜。**
4. **把自己当模块 Owner**，而不是等指令的执行者。

### 群里协作的一条具体规矩

> 「客户发送问题的时候，如果有人在处理，可以用一个 get 表示知道这个问题，在正在处理」——用来防止多人重复处理同一个问题。

### 沟通红线（被反复纠正的）

- 只回「OK」；挤牙膏式回复；该在群里说却私聊
- 模糊承诺——「后续持续跟进」在他这里等于「下次请你吃饭」
- 把简单任务包装复杂；AI 直出交付物不经自己手
- 周报造假；日报没有思考

### 调研与工作坊的两条关键设计

- **调研**：先收齐对接人、样本和权限，明确「谁确认结果」，再谈工期和投入。不要以功能清单切入，否则接口会被收窄。
- **工作坊分组**：「同一条业务链的人放一组」。灰度 8 组 31 人、基本半导体 8 组 12 部门，两次都验证过。
