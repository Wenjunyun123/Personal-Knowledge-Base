## 项目简介

Headroom 是一个开源的 LLM 调用中间层项目，可以在不影响结果准确度的情况下，根据任务类型的不同直接节省 20% 至 95% 的 token 消耗。该项目已在 GitHub 上获得 66.5k stars，并登上了 GitHub Trending。

## 核心原理

Headroom 可以以代理（Proxy）等多种方式接入。当你在 Claude Code、Codex、Cursor 等 Agent 中发出请求时，Headroom 会拦截请求，并从以下三个角度对提示词进行优化与压缩：

-   **缓存对齐（Cache Alignment）**：稳定请求开头的内容，让大模型服务商的 KV 缓存能够命中，避免重复计算。
-   **格式特定压缩**：根据不同的内容类型使用不同的压缩算法，例如 JSON 有对应的压缩算法，代码也有对应的压缩算法。
-   **完全可逆**：所有压缩都是可逆的。如果需要原始文本，AI 可以直接拿回，不会丢失任何信息。

![[笔记同步助手/images/1297385c436da7775d1f0faaacc7fc56_MD5.jpg|Headroom 的三个优化角度：缓存对齐、格式压缩、完全可逆]]

## 实测效果

创作者准备了一个开源项目 Super Base，使用多段不同的提示词、相同的工具、同一个模型，观察使用 Headroom 前后的 token 消耗情况：

-   **第一次**：使用 Headroom 后 token 反而比未使用时多出一倍，原因是触发了多 Agent 调用流程。
-   **第二次**：总 token 看似更多，但大部分是从缓存读取的，非缓存输入比之前少了一万多。
-   **第三次**：输入缓存从未使用直接降至 216，效果非常突出。
-   **第四次**：大部分 token 都使用到了缓存。
-   **第五次**：非缓存输入明显降低，但相对没那么夸张。

在测试基准库下的精度对比中，准确度几乎没有受到影响。整体试用下来，模型输出结果并未出现降智或输出内容减少的情况，因为 Headroom 主要通过压缩格式而非修改提示词的方式实现优化。

## 可视化面板

Headroom 自带一个可视化面板，会持续记录经过它的请求节省了多少 token，并展示节省主要发生在哪些方面。随着请求不断进来，节省的 token 数值也会持续累积。

## 总结

总体试用下来，加入 Headroom 后确实能节省大量 token，且模型输出质量没有出现明显下降。创作者表示后续会继续使用，并长期观察是否真的能持续节省 token 成本。

### 实测：用 Superbase 多场景验证

接入后，我准备了一个开源项目 Superbase，使用多段不同的提示词、同样的工具、同一个模型，观察使用前后的 token 消耗，发现了一些很有意思的事情。

第一段提示词下，使用 Headerroom 比没有使用 token 整整多了一倍。然后我赶紧去看了一下，原来是因为大模型调用了多 Agent。

第二次就很符合 Headerroom 的特点了。虽然总 Token 更多，但大部分都是从缓存读的，被缓存的 Token 比之前少了一万多。

第三次就更厉害了，输入缓存直接从未安装时的五千多降到了二百一十六。

第四次也是一样的效果，大部分 token 都使用到了缓存。

最后一次没有像之前那么夸张，但是非缓存的输入也确实低了很多。

### 可视化面板

平时我们自己还有个可视化的面板，这个面板会持续记录经过它的请求节省了多少 token，主要存在了哪些方面。随着不断有请求进来，节省的 token 数值也会越来越多。

总体试下来，我发现加了 Headerroom 之后确实能节省 Token，模型的输出结果也并没有出现降质或者输出内容减少的情况。毕竟 Headerroom 主要是通过压缩格式的方式，而不是修改提示词。
