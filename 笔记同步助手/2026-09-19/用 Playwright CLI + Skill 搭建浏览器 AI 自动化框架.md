## 一、这套自动化框架能做什么

借助 Playwright CLI 作为浏览器自动化底座，再配合 Claude Code 或 Codex 这类 AI Agent，配合专门的 Skill，可以让 AI 自动操作浏览器，代替人工完成一切机械重复性的工作。其核心优势在于：

-   特别省 Token：很多固定工作流全程不需要 AI 参与，零 Token 就能跑起来。
-   典型应用场景：

-   零 Token 抓取电商网站评论并导出为 CSV 文件；
-   自动把 Markdown 文章发布到 X（Twitter）；
-   对自己开发的 Web App 进行 AI 自动化测试。

-   无需懂浏览器相关知识，只用自然语言就能完成任务。

技术选型上，本方案使用 Playwright CLI 作为浏览器自动化工具，搭配 Claude Code / Codex 作为 Agent 框架，并以 Skill 作为说明文档。Playwright CLI 是微软 2026 年初开源的全新浏览器自动化工具，根据官方基准测试，它比传统的 Playwright MCP 方案能减少约 4 倍的 Token 消耗。

工具搭建好以后，可以把固定工作流沉淀成 Skill，让 AI 既快又省地完成任务。熟练后，许多固定流程甚至可以完全脱离 AI 执行。

## 二、准备工作：环境安装

在开始之前，需要先准备好以下环境：

1.  **安装 Node.js**：如果电脑上没有，可前往 Node.js 官网，根据操作系统下载对应的安装包。
2.  **安装 Playwright CLI**：打开命令行终端，执行官方安装命令。
3.  **安装 Chrome 浏览器**：推荐使用 Chrome，Edge 也可以，但 Chrome 兼容性最佳。

AI Agent 如果需要更详细的网页结构信息，就可以选择读取这个快照文件获取详细信息；不需要则可以跳过。这正是 Playwright CLI 比 MCP 更省 Token 的核心原因：MCP 会把网页内容全部塞进上下文，而 Playwright CLI 可以由 AI 按需读取。

同样以「按需加载」思路设计的还有 `screenshot` 命令：它只是给浏览器截一张图，以 PNG 文件的形式保存在本地，AI 自行决定是否读取，而不是像 MCP 那样直接把图片塞进上下文。

### 3\. 持久化参数：--persistent

`--persistent` 参数表示把 Cookie、登录状态、本地存储等数据写入磁盘，下次使用时直接读取，避免每次重新登录。例如带着 `--persistent` 参数执行命令后，再打开 Google 已经是登录过的状态了。

## 四、接入 AI Agent：Claude Code 与 Codex

Playwright CLI 是一个新诞生的命令行工具，AI 并不知道该如何使用这些命令，所以需要给 AI 搭配 Skill 一起来使用：Playwright CLI 作为技术底座，Skill 作为说明文档，二者搭配取代传统的 MCP 模式，这也是最近的技术发展趋势。

1.  新建一个项目文件夹；
2.  在文件夹中打开命令行终端，执行安装命令，把 Skill 安装到项目目录；
3.  启动 Claude Code，询问「你有哪些 skills」，可以看到 Claude Code 成功读取到 Playwright CLI 技能。

接入 Codex 非常简单：只需要把存放 Skill 的文件夹名字从 `.claude` 改成 `.codex` 即可适配。然后在项目目录中打开 Codex，输入 `/skills` 命令，可以看到 Playwright CLI 在 Codex 里也配置完成了。

基础用法测试：让 AI 使用 Playwright CLI 加上 `--headed` 与 `--persistent` 两个参数打开 Grok，询问今天青岛的天气。AI 成功打开浏览器、来到 Grok 首页、自动输入问题、点击回车、拿到结果并打印到控制台。

## 五、实战案例一：抓取电商商品评论

让 AI 使用 Playwright CLI 查看某商品前 100 条评论，并保存到 CSV 文件。AI 先学习 Playwright CLI 技能，然后打开商品页面。第一次运行总是磕磕绊绊，需要它自己探索、自己寻找解决思路，因此 AI 尝试了很多方案，也浪费了不少 Token。最终虽然成功完成，但上下文窗口消耗了 41%。

### 优化 1：把过程提炼成 Skill

有两种方式可以让下次执行更丝滑、更省 Token。第一种：把过程保存成 Skill。输入提示词「创建一个新的 skill，把刚才打开网站、查看评论、保存评论的全过程以及遇到的坑都提炼出来，保存到这个 skills 里面」，AI 会创建 Skill，把任务里可复用的内容固化进知识。

创建好的 Skill 放到项目目录下后，目录里就有了两个 Skill：Playwright CLI（基础）和「保存评论」流程专用 Skill。先清理上下文，再用相同任务测试。AI 在 Skill 指导下充分吸取了之前的经验，没有出现多余动作，也没有报错，用最低 Token 消耗完美完成任务。

对比数据：

-   第一次（AI 自己摸索）：消耗 41% 上下文窗口；
-   第二次（有 Skill 指导）：消耗仅 5% 上下文窗口；
-   效率提升近 10 倍。

### 优化 2：固化为脚本（零 Token）

抓取评论是完全固定的流程，其实并不需要 AI 进行智能化控制，可以直接编写成固定脚本。输入提示词「把刚才所有的 Playwright CLI 命令汇总成一个脚本，执行脚本就能获取商品的前 100 条评论并保存到 CSV，注意每一步都要有合理的延时与等待」。Codex 编写完成的脚本会先做一轮自测。

查看脚本：以 Windows 电脑为例，这是一个 PowerShell 脚本，AI 以编程方式把步骤都固定下来，例如：

1.  打开商品页面；
2.  确认浏览器中打开的是正确的 URL；
3.  点击「查看全部评价」按钮；
4.  执行 JS 脚本获取评论；
5.  把 JSON 数据保存为 CSV 文件。

在命令行终端中直接执行该 PowerShell 脚本的路径，整个过程不再依赖 Codex 中转，零 Token、零成本完成相同任务。

## 六、实战案例二：自动把 Markdown 文章发布到 X

把视频转成图文教程再发到各平台时，大多数平台发文章都比较简单，唯独 X 发文章步骤非常繁琐。问题主要在于：

-   Markdown 格式不能直接粘贴：格式会错乱，图片展示不出来；
-   HTML 格式可以粘贴，但图片粘贴不过来：图片都变成了「小照相机」占位符，必须手动删除，再一张张手动粘贴。

### 解决思路

1.  使用 Codex 编写 Python 脚本，把文章里的图片下载到本地，从 001 开始编号；
2.  把文章转换成只使用本地图片的 Markdown；
3.  运行 Pandoc 把本地图片的 Markdown 文章转换成 HTML；
4.  让 AI 用 Playwright CLI 自动发文：

-   打开 X 网站，创建新文章；
-   把 HTML 内容粘贴进去；
-   找到所有「小照相机」占位符，按 Backspace 删除；
-   在图片文件夹中找到对应图片，Ctrl+C 复制、Ctrl+V 粘贴，按顺序一张张替换。

把全流程整理成一个 Skill 放到项目目录后，只要给 AI 一个文章路径并告诉它使用这个 Skill 自动发布，就能自动完成发布。Skill 源代码已上传到 GitHub 仓库，感兴趣的可以参考；非 Windows 系统的可以让 AI 参考该 Skill 改写。

## 七、实战案例三：Web App 自动化测试

这套浏览器自动化流程另一个重要应用是对自己写的 Web App 进行自动化测试。例如对一个简历润色美化网页 App：

1.  输入指令「阅读代码，把从注册开始的主体流程写一个中文的测试文档」；
2.  让 AI 使用 Playwright CLI 打开网页，根据测试用例完成测试。

AI 通过阅读代码学习到项目功能，确认主体流程后开始编写中文测试文档，包含第一步做什么、第二步做什么、第三步做什么等。然后用 Playwright CLI 打开浏览器：自动点击注册按钮、创建测试账号、完成登录、创建测试简历并上传，完成主体流程测试，测试结论：通过。

还可以进一步要求 AI 编写更多测试用例，用 Playwright CLI 全自动测试；结合 Claude Code 这类待定任务 Agent 框架，让它定时对系统进行测试，一旦代码改动引入 Bug，AI 就能自动发现并通知，省去大量人工测试成本。

## 八、整套流程总结

1.  **准备阶段**：安装 Node.js、Playwright CLI、Chrome 浏览器。
2.  **接入 Agent**：选择 Claude Code / Codex，把 Playwright CLI 的 Skill 安装进去。
3.  **首次执行**：给 AI 一个复杂任务，让它自己摸索并执行完。
4.  **提炼 Skill**：让 AI 把执行结果和踩过的坑总结成 Skill，避免重复踩坑。
5.  **二次执行**：在 Skill 指导下，Token 消耗可降低约 10 倍。
6.  **固化为脚本**：对完全固定化的流程，让 AI 编写成脚本，直接执行即可，Token 消耗降为 0。

按这套流程，每个人都可以编写出属于自己的 Skill，逐步把日常工作自动化。

## 全文整理

这套流程可以让 AI 自动操作浏览器，代替人完成一切机械重复性的工作，而且特别省 token。很多工作流甚至全程不需要 AI 参与，零 token 就能把自动化任务跑起来。比如，可以零 token 抓取电商网站评论并导出成 CSV 文件，自动把 Markdown 文章发布到 X 平台，以及对自己开发的 Web App 进行 AI 自动化测试。我们不需要懂浏览器的相关知识，只用自然语言就能完成这些任务。

本期视频使用的 agent 框架是 Claude Code 或 Codex，浏览器自动化方案是 Playwright CLI 搭配配套的 skills。Playwright CLI 是二六年初微软开源的全新浏览器自动化工具，根据官方基准测试，比起传统的 Playwright MCP 方案，差不多能够减少四倍的 token 消耗。工具搭建好以后，我们可以把很多固定的工作流程沉淀成 skills，让 AI 既快又省地完成任务。熟练后你会发现，很多固定流程甚至不需要 AI 参与，只需要让 AI 编写好一个固定的脚本，就可以零 token 全自动完成工作。

### 准备工作

在开始之前，我们需要先确保电脑上安装了 Node.js。如果没有安装，可以到 Node.js 官网根据自己的操作系统下载对应的安装包。然后打开命令行终端，输入相应命令安装 Playwright CLI。

下一步要确保电脑上安装了 Chrome 浏览器，使用 Edge 浏览器也可以，不过更推荐 Chrome。准备工作完成后，我们可以用以下命令进行测试：使用 Playwright CLI 操作 Playwright 浏览器打开谷歌官网。最后一个参数 `--headed` 表示使用有头浏览器；如果不加这个参数，Playwright 默认使用无头浏览器。无头浏览器在后台静默运行，虽然比较省内存，但看不到浏览器页面，所以为了方便调试，一般会加上 `--headed` 参数。

同样的思路也体现在截图功能上。`--screenshot` 是给浏览器截图，截屏时会以 PNG 文件的形式保存到本地电脑上，由用户决定是否读取，而不是像 MCP 那样直接把图片塞入 AI 的上下文。

另一个重要参数是 `--persistent`，表示把 cookie、登录状态等数据写到磁盘里，下次使用的时候继续读取，不需要每次重新登录。例如带着这个参数执行命令打开谷歌首页时，因为之前登录过，打开的就是已经登录过的状态。

### 接入 AI Agent

下一步把 Playwright CLI 接入 AI agent。本期视频主要使用的 agent 框架是 Claude Code 和 Codex。

Playwright CLI 是一个新诞生的命令行工具，AI 并不清楚该如何使用，所以需要给 AI 搭配 skills 来一起使用：Playwright CLI 作为技术底座，skills 作为说明文档。CLI 加 skills 搭配使用，可以取代传统的 MCP 模式，这也是最近的技术发展趋势。

先新建一个项目文件夹，打开这个文件夹，打开命令行终端，输入相应命令给文件夹安装 skills。安装完成后，skills 放到了项目文件夹的指定目录下面。然后启动 Claude Code，询问它有哪些 skills，可以成功读取到 Playwright CLI 技能，这样就成功接入了 Claude Code。

对于 Codex 这套框架，我们只需要在项目目录里把存放 skills 的文件夹名字从 `.claude` 改成 `.codex` 来适配 Codex。然后在同一个目录里打开 Codex，输入 `/skills` 命令，列出了 Playwright CLI，说明在 Codex 里也配置完成了。

在 Codex 里测试基础用法：让它使用 Playwright CLI 加上 `--headed`、`--persistent` 两个参数打开 Grok，询问今天青岛的天气怎么样。AI 成功打开浏览器，来到 Grok 首页，自动输入问题，自动点击回车，拿到了结果，最终成功打印到控制台上，任务完成。

### 把流程沉淀为 Skill

来看一个更复杂的例子：使用 Playwright CLI 查看某个商品的前一百条评论，并保存到一个 CSV 文件里。AI 先学习 Playwright CLI 技能，然后打开了商品页。第一次运行总是磕磕绊绊的，不过让它自己探索、自己寻找解决思路即可。AI 尝试了很多方案，也浪费了不少 token——这里显示用掉了百分之四十一的上下文窗口——最后成功完成任务，获取到了 CSV 文件，抓取到了这一百条数据。

我们有两种方式把这个流程总结并保存下来，让它下一次执行更顺畅、更省 token。

第一种方式是把这个过程保存成一个 skill。输入提示词：创建一个新的 skill，把刚才打开网站、查看评论、保存评论的全过程以及遇到的坑都提炼出来，保存到 skills 里，后面只要让你执行保存评论的任务就能调用这个 skill。AI 帮我们创建了 skill，把任务里可以复用的内容固化进了知识。再让它修改一下，把 skill 放到项目目录里，skill 成功放到了项目目录下面。现在项目里有两个 skill：一个是 Playwright CLI，另一个就是刚才保存评论那个流程的 skill。

清理一下上下文，再用相同的任务测试。有了 skills 的指导以后，效果就不一样了：AI 充分吸取了之前的经验，没有再出现多余的动作，也没有报错，用最低的 token 消耗完美完成任务。第一次让 AI 自己摸索、自己试错用了百分之四十一的上下文才完成的任务，第二次有了 skills 的指导，只用了百分之五的上下文就完成了任务。通过把过程提炼总结成 skills，获得了将近十倍的效率提升。

### 完全固定化：编写脚本

抓取评论是一个固定流程，其实并不需要 AI 进行智能化的控制，可以直接编写成一个固定的脚本。输入提示词：你把刚才所有的 Playwright CLI 命令汇总成一个脚本，执行脚本就能获取商品的前一百条评论并保存到 CSV 文件里，注意每一步都要有合理的延时与等待，确保任务成功；脚本写完先测试一轮。很快 Codex 编写完成了脚本，并自己测试通过。

在 Windows 电脑上，这是一个 PowerShell 脚本，AI 以编程的方式把刚才的步骤固定下来了：第一步打开商品页面，第二步确认浏览器里打开的是正确的 URL，第四步点击"查看全部评价"按钮，第六步执行 JavaScript 脚本获取评论，最后一步把 JSON 数据保存成 CSV 文件。

打开命令行终端，输入这个 PowerShell 脚本的路径回车执行，整个流程中间没有 AI 参与。这次不再依赖 Codex，直接执行 PowerShell 脚本，零 token 零成本就完成了任务，并取得了相同的效果。

### 流程总结

总结一下这套浏览器自动化的流程：

第一步（准备阶段），安装 Node.js、Playwright CLI 以及 Chrome 浏览器。第二步，选择你喜爱的 AI agent 工具，把 Playwright CLI 的 skill 安装进去。第三步，给 AI 一个复杂的任务，让它自己摸索并执行。第四步，让 AI 把刚才的执行结果提炼总结成 skill，避免再踩之前遇到的坑。第五步，重试相同的任务，AI 在 skills 的指导下可以把 token 消耗降低十倍。第六步，如果是完全固定化的流程，可以继续让 AI 把这个过程直接编写成一个脚本。有了脚本以后，可以直接执行脚本完成任务，完全不需要 AI 参与，把 token 消耗直接降低到零。

### 实战案例：自动发布文章到 X 平台

来看一个实战案例。最近把视频用 AI 转成图文教程，然后发到各个平台上。大部分平台发文章都比较简单，唯独 X 平台发文章的步骤非常繁琐。

这是一篇 Markdown 格式的笔记文章。这种格式的文章不能直接以 Markdown 格式粘贴过来：首先格式会错乱，其次图片都展示不出来。测试 HTML 格式可以粘贴，但又出现新问题：图片粘贴不过来，都变成了小照相机符号。只能手动先把小照相机删除，再把图片复制过来一张张手动粘贴，非常麻烦。

接下来使用前面介绍的自动化流程把发文章的全过程进行 AI 自动化。还是使用 Codex，让它编写一个 Python 脚本：把文章里的图片下载到本地，从零零一开始编号放到指定文件夹里，先转换成只使用本地图片的 Markdown 文章，然后运行 Pandoc 把本地图片的 Markdown 文章转换成 HTML 格式，注意 HTML 里每张图都应该是独立段落。

AI 编写好了脚本，并转换好了文章：图片都放到了 images 文件夹下面，文章已经转换成 HTML 格式。下一步让 AI 帮我们自动发文。输入提示词：使用 Playwright CLI 先打开网站创建一个新文章，把 HTML 内容粘贴进去，找到所有小相机图标的位置，先按退格键删除小图标，然后在图片文件夹里找到图片，先复制再按 Ctrl+V 粘贴。小图标的数量跟图片的数量相等，需要按顺序替换。

AI 打开了浏览器，创建了新草稿，把 HTML 格式的文章粘贴进去，然后开始一张张上传图片，把原来的占位符删除，再一张张替换成真正的图片。整个过程非常顺利。

把从头到尾的全流程整理成一个 skill 放到项目目录里：只要给一个文章就能自动发布。AI 固化了一个 skill，编写好了技能，生成了配套脚本，这个 skill 可以覆盖自动发稿的全流程。以后只要给它一个文章路径，告诉它使用这个 skill 自动发布，它就能自动把文章发布上去。

这个 skill 的源代码已经上传到了 GitHub 仓库下面，感兴趣的可以参考试一下。不过这是 Windows 电脑的版本，如果是其他操作系统，可以让 AI 参考这个 skill 来改一下。相信按照这套流程，大家都可以编写出属于自己的 skill。

### 自动化测试自己的 Web App

这套浏览器自动化流程的一个重要应用，就是对自己写的 Web App 进行自动化测试。比如这里开发了一个简历润色美化的网页 App。接下来输入指令：阅读代码，把从注册开始的主体流程写一个中文的测试文档，然后再用 Playwright CLI 打开网页，根据你的测试用例完成测试。

AI 通过阅读代码学习到了这个项目的功能，确认了主体流程，接着编写了测试文档，包含第一步做什么、第二步做什么、第三步做什么。然后 AI 使用 Playwright CLI 打开了浏览器，自动点击注册按钮，创建测试账号，完成了登录，创建了一份测试简历并上传上来，完成了主体流程的测试，测试结论是通过。

也可以要求 AI 编写更多的测试用例，使用 Playwright CLI 进行全自动测试；还可以使用 OpenCloud 这种待定任务的 agent 框架，让它定时对系统进行测试。一旦代码里出现了 bug，AI 就能全自动发现并告诉我们，省去很多人工测试成本，对开发网页 App 会很有帮助。
