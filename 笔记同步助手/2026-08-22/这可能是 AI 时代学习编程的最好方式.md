## 二、课程长什么样：从代码到可视化的完整讲解

生成的课程是一份 HTML 页面，用大白话解释每一段代码的结构，并说明所有模块是如何连接起来的。下面是课程的几个核心模块。

课程会先告诉你这个产品主要的功能是什么，下面有哪些 components，然后帮你梳理一遍用户的旅程。所有计算机专业术语，鼠标悬停上去都会有大白话的解释。

## 三、为什么要做这个 Skill：作者自己的痛点

作者不是学计算机专业出身的，但用 AI vibe coding 做了很多项目。每次做完，作品是 work 的，作者很开心，但**不知道它为什么 work，也不知道底层是怎么运转的**。

作者希望能理解它，但又不想从零开始啃计算机基础知识——那样太枯燥了。作者的结论是：

> 学习计算机最好的材料，就是你自己 vibe coding 出来的产品。因为你已经得到过正反馈，而且非常清楚你的产品是怎么运转的，所以你会更有动力去理解它背后的代码。

## 四、AI 时代的教育哲学：Build First, Learn Later

传统学校的学习路径是**先学后做**：先上好几年基础课，学一堆很理论的知识，很长时间以后才能应用，过程非常枯燥。

有了 AI 之后，可以反过来——**先做后学**（Build First, Learn Later）：先不管三七二十一让 AI 帮你做出来，得到正反馈，然后再倒回去问 AI：_这个背后是怎么 work 的？用可视化的方式给我讲一下_。作者认为这是对成年人来说更可持续的一种学习方式。

## 五、整体设计原则：可视化沟通

作者贯穿整套课程的设计原则是**可视化沟通**：尽量不用大段文字，而是用可视化的方式去展示。人不愿意读大段的文字，而可视化更利于理解和集中精力。

## 六、Coding：从一个职业变成一项技能

以前只有专业程序员需要学 coding。但作者认为，有了 AI 之后，**人人都应该掌握一些 coding**。

这里的 coding 不是说你要从头去手敲代码，或者去理解它的语法，而是说——

-   要有**驾驭 AI coding 的能力**；
-   能**辨别出 AI 的一些错误**；
-   能够**有效引导 AI 去做更高层的决策**。

因此，作者在整个 prompt 里设定的学习目标，都是围绕"驾驭 AI 写代码"这件事，而不是传统意义上的语法与理论。

## 七、给非 CS 背景学习者的建议

如果大家并不是专业的计算机背景，但又想通过 vibe coding 去做一些东西、学一些代码基础知识，作者比较推荐以下学习方式：

-   **不要**去上 bootcamp。

我最近做了一个叫 code-based-course 的 skill，它能把任意一个代码库转换成一门代码课，让你通过自己的项目来学习写代码。这个项目目前在 GitHub 上有五百多颗星，推特上也获得了不少浏览量。

先看一下它的效果。比如这是我想要理解的一个代码库，这是转换完成后的课程页面，它是一个 HTML 文件。整个课程会用通俗的语言解释每一段代码的结构，以及各个部分是如何连接的。它会先说明这个产品的主要功能是什么，下面有哪些 components，然后帮你梳理用户的旅程是什么样的。所有出现的计算机专业术语，鼠标放上去都会有通俗化的解释。

另一个我非常喜欢的非代码解读方式是：我让 AI 抽取一些关键的代码块，左边是原始代码，右边则把代码翻译成大白话，这样你就可以像中英对照一样去理解代码。这些翻译后的语句鼠标放上去同样也有进一步的解释。

课程还会给你出题，它会隔三差五地提出两道问题，让你巩固已经学过的内容。它还会把代码库里各种 API、components 等以比喻的方式帮你理解它们的作用以及彼此之间的连接方式，同时配有可视化的 file tree。

其中一个特别有意思的部分是：我用 HTML 做了一个交互页面，让你直观理解用户在使用这个产品时，背后究竟在发生什么，数据是如何流动的。

最让我觉得有意思的一个部分是：让课程以群聊的方式来展示不同的 API 和文件之间是怎么交流、互相发 message 的，就像一群人在一个群里聊天一样。这样你就能非常清晰地理解代码库里不同模块之间是如何连接的。

后面还配有 architecture diagram 等等。通过这样一个完整的 HTML 课程，你基本上就能理解你这段代码背后到底是怎么运转的。

### 为什么做这个 skill

我做这个 skill 的初衷是：我并不是计算机专业出身，但现在我用 AI vibe coding 做了不少项目。每次做完之后，它确实能 work，我也很开心，但我并不清楚它为什么 work，底层是如何运转的。我还是希望能去理解一下，可我又不想从零开始学计算机基础知识，那个过程对我来说太枯燥了。所以我觉得学习计算机最好的材料，就是你自己 vibe coding 出来的产品，因为你已经获得过正反馈，而且你很清楚你的产品是怎么运转的，所以你会更有动力去理解它背后的代码。这也是我对 AI 时代学习与教育的一个理解。

### 先做后学

传统在学校里的学习模式是先学后做：先上好几年的基础课，学一些偏理论的知识，可能很长时间以后才能去应用它，整个过程非常枯燥。但我觉得现在有了 AI 之后，我们可以把顺序倒过来，也就是先做后学。我一直说 "build first, learn later"：先不管怎样，让 AI 帮你把东西做出来，它 work 了，你先获得了正反馈；然后再回过头去学习，去问 AI 这背后是怎么 work 的，并让它用可视化的方式讲解给你。我个人觉得这是对成年人来说更可持续的一种学习方式。

### 设计原则：可视化沟通

我的整体设计原则是可视化沟通。大家可以看到，整个课程里不会有特别多大段的文字，它会尽量用可视化的方式来呈现。因为人不愿意读大段的文字，可视化能让信息更易于理解，也更容易让人集中注意力。

另外，coding 正在从一个职业变成一项技能。以前只有专业的程序员需要学 coding，但有了 AI 之后，我觉得人人都应该掌握一些 coding。这里的 coding 不是说你要从头开始手敲代码，或者去理解它的语法，而是说你要有驾驭 AI coding 的能力。所以我在整个 prompt 里设定的学习目标，都是让用户能够具备驾驭 AI 写代码的能力，能够辨别出 AI 的一些错误，并有效地引导 AI 去做更高层的决策。
