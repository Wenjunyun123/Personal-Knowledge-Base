## 一、范式转变的信号：Claude Code 引发讨论

## 二、国内的主角：飞书多维表格智能体

虽然很多人用不了 Claude Code，但今天讨论的核心是国内人人都在用的飞书，以及它新推出的「多维表格智能体」。这个看似拗口的七个字名字，背后有清晰的业务定位。

## 三、为什么"小龙虾"（Hermes）没能真正落地？

回想 Hermes 流行的那段时间，大家经常在飞书群里 @小龙虾，场面热闹。但它能帮的无非是搜个新闻、做简报、做 PPT，而且经常崩。根本原因是：

-   Hermes 始终是"业务之外"的东西
-   想用好它就要搭一堆桥梁，打通到内部数据库、CRM 等系统
-   还要担心它可能的误操作

这天然就有门槛——不是装上、调教一下就能工作的。

## 四、飞书多维表格智能体的核心优势

-   **一键创建**：点点鼠标、输入要求，Agent 就建好了
-   **链接分享**：把链接丢到群里就自动拉入群，任何人都能用

-   **权限天然隔离**：自动识别群里每个人的权限，不用担心越权
-   **主动预警**：不是定时任务，而是重要事件发生时自动触发

## 五、社会学视角：共同知识与 Team Agent 文化

它真正解决的，是企业落地 AI 的最大痛点——不是"怎么做 Agent"，而是"大家不愿意用 AI"这件事。一个事物的流行，不能只看技术和产品层面，更要从社会学层面剖析。

以前在社群里组织活动特别难：发了通知没人说话、没人报名。但有人发明了"接龙"之后，群里就活跃起来。这就是社会学里「共同知识」的概念——不是单纯"大家都知道"，而是"我知道你知道，你也知道我知道你知道"。

当一个员工发了自己做的 Agent 并被点赞，这就是建立了一个共同知识：

-   浅层：加速了 Agent 能干什么、怎么交互的 know-how 在团队里传播
-   深层：那些想躺平、想不学 AI 的人越来越难——你分享一个 Agent 到群里被点赞，其他人就会去效仿

一种基于团队的「Team Agent」文化就会慢慢兴起。别人做的 Agent 被分享、被使用多少次，其他人都看在眼里。所以 Karpathy 提的是范式转变，而我看到的是"人人都做 Agent"的浪潮可能真的要来了。

## 六、实操演示：搭建一个能干活的多维表格智能体

### 6.1 准备底表（附一个求职小技巧）

如果你想应聘或投身 FDE 行业，想做一套表格练手：去官网找行业伙伴案例丢给 Codex，让它扒一下这家公司的招聘信息。从这两份资料大概就能模拟构造出该公司的人员结构和业务流程基础数据。我就用这种方法建好了一张电商多维表格，店铺、商品、投放、订单、库存、人员权限都已经在里面。

![[笔记同步助手/images/04335ef3dccd576b9825e133e82c6394_MD5.jpg|电商场景的多维表格底表：店铺、商品、投放、订单、库存]]

### 6.2 创建智能体 + 挂载知识库

在飞书多维表格里创建 Agent，把刚才的多维表格选为知识库——它就自动获得了该表格的操作权限。

### 6.3 用自然语言配置触发器

过去实现"业务事件 → 自动响应"需要写程序，现在直接和智能体对话就行。例如：

> "当 ROI 跌破某阈值时，去群里圈对应的负责人通知他，并同步到管理群。"

为了演示，我手动改了 ROI 数据，很快智能体就在运营群里圈了负责人，同时在管理群同步了这条信息。如果配合"一键投放、调整预算"的功能，还可以用卡片直接通知，负责人点一下卡片就完成了操作。

### 6.4 更多场景与 @ 调用

类似地，可以配置：

-   库存可售天数跌到 7 以下 → 喊供应链补货
-   高价值客户 30 天没复购 → 通知运营

不光是通知，还可以直接 @它 问"到底是怎么回事"，让它帮你查表找原因；也可以通过配置各种丰富的技能实现更复杂的任务。总结起来就是一句话：你甚至不需要打开多维表格，经验就自动沉淀成了一个 24 小时在线的 AI 员工。

### 7.2 安全：权限天然隔离

很多老板会担心：这么猛的东西，万一乱看数据、乱改表、看到不该看的东西怎么办？答案是：系统会根据实际发起人的数据权限和配置来决定它能干什么——你问了不该问的问题，智能体根本没有权限回答。

这就是和 Hermes 的最大区别：

-   Hermes 的权限要么太大、要么太小；想精细控制就得做一套很复杂的系统
-   多维表格智能体本身"住在"表格里，权限隔离天然轻松实现

当然也可以两者结合：让多维表格智能体在事件发生时去群里圈 Hermes，让 Hermes 去干更复杂的活。

## 八、把你的经验变成可署名资产

一个很现实的问题：哪些 SKU 要清仓、哪些要补货、哪些 ROI 掉了其实跟投放没关系——这些是我多年踩坑锻炼出来的"直觉"。如果我把它做成智能体，别人一键复刻走，我图啥？这不是加速自己被淘汰吗？

过去很多人的安全感都来自于"只有我知道"，但现在经验已经不存在黑箱了——它就住在表里。同时它还会放大另一群人：能把经验变成系统、变成标准、变成 Agent 的人。

所以建议是：不要让你的经验停留在脑子里，要让它变成可运行、可统计、可署名的资产。早点成为这样的人，这场浪潮里你就是那个吃螃蟹的人。

## 九、为什么叫这个拗口名字？

企业转型 AI 的根子，从来都不是模型能力。"多维表格智能体"这个名字看似复杂，实则简单易懂、务实低调——它直接告诉用户：智能体住在表格里、为业务服务。

可能很多朋友会说，我们根本用不了 Claude 呀，何来浪潮之说？我们不用 Claude，今天讨论的主角是国人都在用的飞书，以及它新推出的多维表格智能体。

### 飞书多维表格智能体：让 Agent 真正落地业务

听到「多维表格智能体」这七个字，很多朋友又要笑了——你又在尬吹。这长串七个字的复杂名字都记不住，它怎么能火呢？在群里艾特智能体，这有什么了不起的？

没错，小龙虾流行的那段时间，大家应该经常在飞书群里圈小龙虾，那个场面谁都经历过。热闹了半天，但没有落地什么，对不对？能帮你搜个新闻、做简报、做 PPT 什么的，但经常会崩。因为小龙虾始终是你业务之外的东西，你想用好它，就得搭一堆桥梁，把它打通到内部数据库、CRM 等等，还要担心它可能的误操作。这天然就是有门槛的，不是说装了龙虾、调教了龙虾，它就能去工作。

但如果有一个简单的办法：你点点鼠标、输入要求，Agent 就创建好了；你把链接分享到群里，就自动拉入群了，任何人都能使用；一艾特它，它就会基于真实的数据来回答，还知道群里每个人的权限，不用担心有人用它干坏事；而且它会自动说话，不是小龙虾那种定时任务、也不是心跳，而是当重要的事情发生的时候，它自动出来预警。

如果你还不信这是趋势，那我告诉你本质吧：它解决的是企业落地 AI 的最大痛点——不是怎么做 Agent，而是大家不愿意用 AI 这件事。

### 从社会学角度：为什么浪潮一定会来

多年的经验告诉我，一个事物的流行不能只看技术层面和产品层面，更需要从社会学层面去剖析。很早以前，社群里组织一个活动特别难，发了活动通知没人说话、没人报名。但是后来有人发明了接龙，群里就活跃起来了。这其实就是社会学里「共同知识」的概念——不是单纯大家都知道，而是「我知道你知道，你也知道我知道你知道」。是不是很绕？当一个员工发了自己的 Agent 之后，很多人给他点赞，这就是建立了一个共同知识。

往浅一层说，这种行为加速了 Agent 能干什么、怎么交互的 know-how 的传播；往深一层说，那些想躺平、想不学 AI 的人越来越难了。道理跟接龙一样，你分享一个 Agent 到群里，如果被点赞，那其他人就会去效仿。这时，一种基于团队的 Team Agent 文化就会慢慢兴起。别人做的 Agent 如果被分享了、使用了多少次，其他人都是看在眼里的。所以卡帕西提到的是范式转变，而我看到的是人人都做 Agent 的浪潮可能要到来。

### 手把手教你搭建一个能干活的多维表格智能体

不要紧，接下来我会手把手教你怎么用好它，搭出一个能干活的多维表格智能体。

首先一个小技巧：如果你要应聘或者想要投身 FDE 行业，想做一套表格操练一下，我教你个办法——你去官网找行业伙伴案例，丢给 Codex，并且让它去扒一下这家公司的招聘信息。从这两个信息，大概就能模拟构造出一个公司的人员结构、业务流程的基础数据。我就用这种方法已经建好了一张电商的多维表格，店铺、商品、投放、订单、库存、人员权限都在里头。

我还是用上次那个熟悉的产品「如果 ROI 跌了应该怎么办」来演示。首先我创建好 Agent，给他的知识库选择多维表格，这时候他就有了这个表的操作权限。接下来我们要做一个触发器：企业的业务在运行过程中会发生无数的事件，发生了一个事件应该做什么，这就是触发器。在过去我们是要用程序来实现的，现在你跟多维表格智能体对话就好了，直接提出你的要求：

「我要求当 ROI 跌破 2 的时候，去群里圈对应的负责人通知他，并同步到管理群。」

为了演示方便，我这次就手动改了 ROI。很快智能体就发送了预警，在运营群里圈了负责人，同时还在管理群同步了这个信息。如果你有一个一键投放、调整预算的功能，你甚至还可以用卡片直接通知，然后负责人点一点卡片就直接搞定了。

我们再来看几条：库存可售天数如果跌到 7 以下，他会喊供应链补货；高价值客户 30 天没复购，他会通知运营。所以不光是通知，你还可以艾特他问到底是怎么回事，让他帮你查表、去找原因，甚至通过配置各种各样的丰富技能实现更复杂的任务。实现这些就是一句话，你甚至不需要打开多维表格，经验就自动沉淀成 24 小时的 AI 员工。

### 老板的担心：会不会乱看数据、乱改表？

但是看到这里，很多老板也会因为一件事而害怕——这么猛的东西，万一乱看数据怎么办、乱改表怎么办？会不会看到一些不该看的东西？

不用担心，系统会根据实际发起人的数据权限和配置来决定他能干什么。你问了不该问的问题，对不起，智能体没有权限回答你。这就是和龙虾的最大区别：龙虾权限是不是太大了？可是你要是不给它权限，它就是个傻子；要仔细控制权限，你就得做一套很复杂的系统。多维表格智能体就很轻松实现了，因为本质上来说，它本身就是住在表格里。

当然你依然可以用龙虾，比如说当事件发生的时候，你让多维表格智能体去群里圈龙虾，让龙虾去干活，这也是可以的。

不过一些聪明的朋友可能已经想到了，比如我很懂哪些 SKU 要清仓、哪些 SKU 要补货，哪些 ROI 掉了其实跟投放没关系，这些都是我多年踩坑锻炼出来的直觉。但我现在把它做成智能体了，别人一键复刻走，我图个啥？这不是加速自己被淘汰吗？

回到最初的观点，飞书多维表格智能体为什么就是要叫这么拗口的名字？其实就是简单易懂、低调务实。企业转型 AI 的根子从来都不是模型能力。Claude Tag 是让 Agent 进了群，而飞书多维表格智能体是让 Agent 直接进了业务。好了，你学到了吗？以上就是本期的全部内容，我们下期见。
