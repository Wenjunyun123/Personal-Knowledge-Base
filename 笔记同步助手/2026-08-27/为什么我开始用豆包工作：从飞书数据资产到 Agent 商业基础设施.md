本期分享一个大多数人没有注意到的视角：当 AI 已经把"干活效率"拉满，为什么我们的收入却没有同比例增长？答案藏在被忽视的"接活效率"里。豆包工作（豆包面向生产力场景推出的全新 Agent 产品与品牌）或许正是撬动这一局面的关键。

## 一、AI 的盲区：只解决了"干活"，没解决"接活"

AI 让工作完成得更快，但收入并没有同比例提高——因为它解决了"干活的效率"，却没有解决"接活的效率"。以自由职业/外包型工作为例：每天有大量来自甲方的询单涌来，读需求、做技术、匹配、调时间、谈报价，一整天十几个回合来回，能成单的却很少。

瓶颈恰恰出在需要与人打交道的环节：读需求、建立信任、谈报价、推进流程——这些只能靠人。直到 AI 能真正帮人"接活"，单纯的生产力提升才会有意义。

## 二、被低估的商业网络：飞书

工作中相当一部分协作其实是从一份飞书文档开始的。一份飞书文档的背后，往往承载着"甲方—乙方"的角色：客户通过链接发起需求，再回到飞书里讨论、修改、签署。无论是个体户、咨询、设计还是开发工作室，几乎所有"商业关系"都已经在飞书上发生。

问题在于：这些沟通"散落在各处，没有被沉淀成上下文"，Agent 自然就没法理解这个生意，也无法参与其中。

更进一步的现实是：大多数人对飞书的使用不到 1%，仅停留在"手动新建飞书文档"的阶段，根本谈不上"在飞书上做批注、争论、解决问题，把整个商业流程留在飞书上"。这恰恰是豆包工作要补上的拼图。

## 三、豆包工作：让飞书能力成为"一等公民"

浅层来看，豆包工作帮助所有人日常提升工作效率；往深了看，它的目标是"为了企业的上下文，为了 Agent 真正进入这个网络"。

### 1\. 意外的"桃花源"初体验

原本对豆包抱有刻板印象——界面不够极客、光是"被发现用豆包录屏可能就要掉粉"。但某天偶然打开豆包，发现可以用飞书账号直接登录，登入之后"好像误入了桃花源"，和 Cursor 几乎分不出区别——后来才意识到，那其实就是豆包工作的灰度版本。

把它和 Cursor 放在一起，外观上看不出明显区别；操作飞书却异常丝滑。如果说与 Cursor 最大的不同，那就是：豆包工作把"所有飞书相关的能力"都做成了一等公民。

![[笔记同步助手/images/1f65ea5775b27c04a738f7a81a251337_MD5.jpg|豆包工作用飞书账号登录的入口与灰度版初体验]]

### 2\. 内置 GUI Agent：从屏幕到云端

豆包工作内置了 GUI Agent，能够直接看着屏幕去操作浏览器、桌面端、移动端；甚至关掉电脑，它还可以在云端继续运行。这是它"越来越像 Cursor"的关键差异点之一。

### 3\. 企业知识连接器：曾经的极难用，现在一键完成

聊天框里直接内置"企业知识连接器"——"连接器"在飞书集成里曾经是一个非常难用的功能，如今豆包直接替你操作。左侧栏还出现了"飞书云盘"，这是日常最高频的应用之一，用了之后甚至连飞书本身都不必再打开。

更关键的细节是：Agent 编辑文档时，"修改过程是高亮显示的"，一眼就能看到 AI 在改哪里——这与 Cursor 的体验有明显差异。

### 5\. 联系人 + 历史上下文：从聊天记录里"取数"

豆包工作内可以直接搜索飞书联系人，查看和该联系人之前聊过什么、开过什么会。举个例子：写文案时，合作方发来一堆新需求，以前需要手动截图给 Cursor；现在只要在豆包里圈下联系人、圈下要改的文档，豆包就会从聊天记录里整理出内容并直接给出修改——"丝滑程度是其他 Agent 难以做到的"。

### 6\. 中文习惯与飞书原生理解

订阅豆包 2.1 Pro 模型后，整体体验"无比丝滑"。其中两个加分项：

-   **中文更符合习惯**：相比海外模型，中文表达更自然；
-   **对飞书流程和功能有"与生俱来的理解"**：这种契合度必须用过才知道。

### 7\. 补齐所有飞书的"皮毛"技能

一个好消息：哪怕只懂飞书皮毛的用户，"也不用学了"——豆包可以直接操作飞书的大多数能力，过去你只会一项技能，借助 Agent 几乎可以"全部精通"。

## 四、真正重要的不是效率，而是 Harness

上述所有效率提升都不是最重要的，也不是让人持续订阅豆包工作的关键理由。真正的答案指向一个更深层的话题——**数据与 Harness（Agent 执行框架）**。

### 1\. The Information 的线索：有人愿意为"聊天记录"付 30 万美元

近期 The Information 的一篇文章很有意思：OpenAI 和 Anthropic 背后的数据公司，开始向创业公司购买数据授权——聊天记录、会议录音、客服工单，最高报价达 30 万美元。

为什么？因为"这里就是人类真实工作中的沟通和决策记录"，是 AI 代表人类进入真实商业网络必须遵循的人类习惯。

![[笔记同步助手/images/aff5ccfc35349f13efc503ea18fcc3ac_MD5.jpg|The Information 报道 OpenAI、Anthropic 向创业公司购买数据授权]]

### 2\. 一个常见的误会：你的数据会不会被拿去训练？

不要误会：使用 Agent 工作，Agent 的公司不会拿你的"使用数据"去训练模型。但"商业发生的过程"本身是可以被统计、被抽象出来的——在这些数据里总结出的人类习惯，可以用来设计"商业 Agent"。

几个典型例子：

-   群里谁一直在潜水、但每次会议都准时出现？——这可能是真正的拍板人；
-   客户说"我们在调研"——到底是客气拒绝，还是真的在走流程？
-   Agent 在做商业判断前，应该分析哪些信息、了解哪些人、走什么流程？

这些都只能从真实"人类习惯"中训练出来——而这些习惯，正是 Harness 的本质。

### 3\. 豆包工作天生就"住在飞书仓库里"

为什么豆包工作天然具备这种能力？因为飞书从诞生的第一天起，所有数据就在云上，归属企业本身——它本身就是一套"在商业流程可追溯的数据"中成长起来的 Harness。未来能第一时间遵循"商业世界水上水下规则"的 Agent，一定是在这样的 Harness 里训练出来的。

如果缺失了这些 Harness，"哪怕能力再强、跑分再高，也只是个打工仔"。那么问题来了：要选一个代表自己的"程序员"，还是一个"精通商业的幕僚"？

这解决的已经不只是生产效率，更是"商业连接的效率"问题——也就是"AI 能不能让我们真正受益"这件事。

无论你是主动在飞书上构筑生态，还是像很多人一样被网络效应"被动"拉进来，或者根本不用飞书和豆包，都应该看到商业网络背后"连接"的本质，以及 Agent 参与这个网络的大趋势：

## 全文整理

豆包工作你用了吗？这是豆包面向生产力场景推出的全新 Agent 产品与品牌，甚至可能成为影响你我业务的基础设施。

### 一个大多数人都没看到的角度

有一个痛苦大家可能有共鸣：AI 让你的工作完成得更快了，但收入没有更高。因为 AI 解决了干活的效率，没有解决接活的效率。

就拿我自己来说：每天各种甲方询单发过来，读需求、做技术调研、算时间、谈报价，一天十几个，但能成的真的很少。接活环节只要有人与人打交道的部分，效率就太低了。

那为什么 AI 这么强，还不能帮我们接活呢？

### 我对飞书的重新理解

我有一个体会——我的工作往往都是从一个飞书文档开始建立的链接。我一搜微信，发现有海量的飞书文档。从一个角度看：无数的甲方和乙方其实都是被飞书文档连接起来，形成了商业网络。

你自己想想，从读需求、谈报价，到建立信任、接活的整个过程，其实都在这个网络里发生着，只是这些沟通散落在各处，没有被沉淀成上下文。Agent 没法理解这个生意，自然就没法参与。

我还发现，大部分人对飞书的开发不到百分之一，都停留在手搓飞书文档的阶段。更别提要尽可能多地在飞书上批注、争论、解决问题，把整个商业流程都留在飞书上。

### 豆包工作的本质

豆包工作就是来解决这个问题的。浅看，是帮所有人日常提升工作效率；往深了看，是为了企业的上下文，是为了 Agent 真正进入这个网络。

我早就意识到应该未雨绸缪构筑这些上下文，以迎接随时可能到来的 Agent 撮合商业的时代。所以我的飞书其实用得蛮多的，但我从来没有想过用豆包。

我有 Codex 二十倍的订阅，用它来操作飞书不就好了，为什么要换豆包？而且之前我对豆包有刻板印象——那个界面的样子吧，就不是给我这种极客用的。再加上还有一点心理压力：万一录屏时被粉丝发现我用豆包，搞不好还要掉粉。

### 一次“误入桃花源”的体验

但前一段时间我好奇打开豆包，发现有个飞书登录。我就用飞书账号登了进去。

哇，那天的感觉就好像误入了桃花源：这还是豆包吗？和 Codex 几乎分不出区别。直到今天我才知道，原来当时那一个就是豆包工作的灰度版本。把它和 Codex 放一起，一眼几乎看不出什么区别，操作上也是。当时我是真的不愿意承认：它操作飞书，真是个丝滑。

要说他和 Codex 除了模型之外最大的区别，就是所有飞书相关的能力都成了一等公民。它还内置了 GUI Agent，能直接看着屏幕操作浏览器、桌面、移动端；甚至你关上电脑，它还能在云端继续跑。

难怪最近总是听到说“豆包越来越像 Codex 了”。但你们看，豆包工作的聊天框里多了一个“企业知识连接器”——这个功能原本是飞书集成里一个极难用的设置，现在豆包直接帮你操作了。左侧栏也出现了飞书云盘，这是我用得最多的功能——这下连飞书都不用打开了。

### 真正丝滑的几个细节

在和 Agent 的对话框里，你可以直接圈一个飞书文档让豆包去改，不用再粘贴链接。甚至在右边文档里选中一段文字，你也可以直接让他来改。Agent 编辑文档的收益和形式都不一样，编辑过程是高亮显示的，在哪里一目了然。

我居然还发现豆包里可以直接搜飞书联系人，可以找到和联系人聊过什么、开过什么会。比方说你正在写文案的时候，合作方发来一堆新需求，以前还得自己截图给 Codex，现在直接在豆包里圈下联系人，再圈下要改的文档，豆包就从聊天记录里把内容整理出来给你改好了。这种丝滑程度，其他 Agent 都很难做到。

再想象一下伙伴对话这里：如果有一天豆包上的伙伴对话也可以添加联系人的 Agent——你接活的 Agent 和甲方的 Agent 都在一个群里——这件事的发生一点都不违和。

所以我当时就订了，因为我一定要试试豆包 2.1 Pro 的模型。可以说真的无比丝滑，中文也比较符合我们的习惯，尤其是它对飞书流程和功能有一种与生俱来的理解。这感觉你得用了才知道。

### 一个好消息

如果你只会一些飞书的皮毛，那你也不用学了，因为豆包可以直接操作飞书的大多数能力。从前你可能只会一点技能，现在全部都精通了。

### 让我一直订阅豆包的真正原因

但这些效率的提升都不是最重要的，也不是能让我一直订阅豆包的理由。主要的原因是什么呢？

最近 The Information 上一篇文章很有意思：OpenAI 和 Anthropic 背后的数据公司，开始向创业公司购买数据——授权聊天记录、会议录音、客服工单，最高报价三十万美元。为什么呢？因为这里就是人类真实工作中的沟通和决策记录。这是 AI 代表人类进入真实商业网络必须遵循的人类习惯。

但大家不要误会：你用 Agent 工作，Agent 的公司并不会拿你的使用数据去训练模型，但商业发生的过程是可以被统计、被抽象出来的。在这些数据里总结出的人类习惯，是可以用来设计商业 Agent 的。

比如说：群里谁一直在潜水，但每次会议都在，哪个人可能才是真正拍板的人？客户说“我们再调研调研”，到底是客气的拒绝，还是认真的在走流程？Agent 在做商业判断前，他应该分析哪些数据、了解哪些人、走什么流程？这都是靠 Harness 训练出来的习惯。

但豆包天生就有这个。因为飞书从诞生的第一天开始，所有的数据就都在云上，也都归属于企业本身。飞书本身就是一套在商业流程可追溯的数据中成长起来的 Harness。未来能第一时间遵循商业世界水上水下规则、能代表人类进入真实商业网络的 Agent，一定是在这样的 Harness 里训练出来的。

如果没有这些，别的能力再强、跑分再高，也只是个打工仔。

### 做一个选择

那你让你去选，你会选一个只会编程的程序员代表自己，还是一个精通商业的幕僚呢？

我不敢说豆包一定会成为最先的 agent，但他离得最近。他就是住在飞书这座仓库里的超级管理员啊。

我必须开始用豆包工作的最重要原因，就是他这个叫豆包的大冒险的灵魂。我不在乎它模型能力能排第几，他只要更懂规则、更懂商业世界的上下文、更懂这个网络，他就能产生最大的价值——不只是生产效率，更是商业连接的效率。从而解决我们能不能因为 AI 真正受益的问题。

### 给自己的要求

我没有办法证明他现在就有这样的能力，所以我必须天天使用、天天磨合，伴随着他的演进，同时构筑我的上下文和基础设施。如果有一天 Agent to Agent 的自动化商业化网络时代突然降临，我必须是最先做好准备的一批人。
