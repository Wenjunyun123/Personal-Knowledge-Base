# Codex 5.6 真正与普通人拉开 90% 差距的，不是 prompt，而是你会不会配置 config.toml

### 01 MODEL + REASONING｜固定默认模型与推理强度

别每开一个任务都重新选模型。

把默认模型和推理强度写进 `~/.codex/config.toml`，日常任务追求速度，复杂架构任务再提高 reasoning effort。

```
# ~/.codex/config.toml
model = "default-model"
reasoning_effort = "medium"
```

对应的工作节奏：

-   **DAILY**：日常任务，FAST
-   **ARCHITECTURE**：复杂架构任务，提高推理强度

输入 prompt：

> 请检查我当前 Codex 5.6 实际支持的模型和 reasoning effort 配置，不要猜测或使用已经废弃的参数；然后修改 `~/.codex/config.toml`，为日常 Coding 设置合理的默认模型与推理强度，并告诉我具体修改了哪些字段、为什么这样配置，最后验证配置是否成功生效。

### 03 PROJECT CONFIG｜每个项目，都有自己的规则

```
/frontend
  └── 自己的规则、栈、测试、工具

/backend
  └── 自己的规则、栈、测试、工具

/mobile
  └── 自己的规则、栈、测试、工具

~/.codex/config.toml    ← GLOBAL CONFIG
```

具体到一个项目目录里：

```
my-project/
├── src/
├── tests/
├── package.json
└── .codex/
    └── config.toml     ← 项目级配置
```

项目级 `config.toml` 里要写清楚四件事：

1.  TECH STACK
2.  TEST
3.  RULES
4.  TOOLS

关键区分：

-   **GLOBAL** = HOW YOU WORK（你在所有项目里通用的工作方式）
-   **PROJECT** = HOW THIS REPO WORKS（这个仓库自己的规则）

-   CHANGE
-   TEST
-   LINT
-   SECURITY
-   VALIDATE
