## PM 的核心工作之一：为研发找到现成的 API

对于一个 AI 产品经理来说，一项非常重要的工作就是**给程序员找 API**。具体来说，需要每天关注 Twitter 等渠道上发布的新产品和新的 API，因为很多能力模型已经能够实现，并不需要自己重新造轮子。

![[笔记同步助手/images/a9cef0f2ee39149799bdd29b1fee6b5d_MD5.jpg|讲解 PM 为研发寻找 API 的观点]]

讲解 PM 为研发寻找 API 的观点

### 关注 AI 进展是 PM 的必备能力

PM 必须持续关注 AI 最新的进展，明确当下模型能力的边界在哪里、可能性是什么、最先进的技术可以实现什么效果。掌握了这些信息之后，再把相应的技术和 API 转发给研发去对接。

这样做的价值在于：研发很多时候耗费大量时间做出的东西，回头发现市面上早就有了，根本不需要再重新做一遍。

## AI 产品正在"乐高化"

现在的 AI 产品越来越像在拼乐高，很少有人会自己发明一项新技术。因为绝大多数团队既不是模型公司，也不做模型训练。应用层真正重要的是：

-   交互要非常好
-   用户体验要非常好
-   产品定位要非常精准

而底层的很多技术，其实都是市面上的 API，大家用的都是同一套。没有太多需要重新发明的东西——但前提是，你得**知道这些 API 的存在**。

## 实例：TLDW 项目中的 API 选型

以自己做过的 TLDW 项目为例，其背后用到了一个叫 **Supadata** 的 API，它专门用来抓取 YouTube 的逐字稿。

![[笔记同步助手/images/a7e7f0aac80862518be6b117af83e898_MD5.jpg|举例 TLDW 项目中使用的 Supadata API]]

举例 TLDW 项目中使用的 Supadata API

很多人在评论区问是怎么抓取 YouTube 逐字稿的，其实市面上已经有非常成熟的解决方案，直接接入即可，不需要自己去写一套抓取逻辑。而之所以能知道有这些新技术的存在，靠的就是每天去看、持续关注。

## 看 AI 新闻本身也是工作的一部分

看 AI 新闻、学习 AI，本身就是工作的一部分。想要做一个好的 AI 产品，就必须了解最新的进展。这一点和移动互联网时代很不一样：

![[笔记同步助手/images/4a102f42009777c9aab5d8bcd3783ea7_MD5.jpg|对比移动互联网时代与 AI 时代技术变化速度]]

对比移动互联网时代与 AI 时代技术变化速度

-   **移动互联网时代**：技术相对稳定，基本就是那套 tech stack，不太需要频繁追新。
-   **AI 时代**：模型能力每天都在发生变化，每天都有新的技术诞生。

一旦不持续关注，做出来的东西很可能就白做了——别人早已用现成的 API 跑通，你还在重复发明轮子。

## 全文整理

作为产品经理，有一项很重要的工作，就是帮程序员找合适的 API。每天我会在推特上浏览，看又有哪些新产品发布，又有哪些新的 API 开放出来，因为很多事情其实已经有现成的模型可以解决，不需要重复造轮子。

我觉得产品经理的一项重要能力，就是持续关注 AI 领域最新的进展，弄清楚当下模型能力的边界在哪里、可以实现哪些效果。掌握这些信息后，就可以把相应的技术和 API 推给研发团队，让他们直接对接。因为很多时候，研发可能会花费大量时间自研一个东西，最后却发现市面上早就有人做过了，根本不必再重新实现一遍。

现在做 AI 产品，越来越像搭乐高。很少有人会去发明全新的底层技术——毕竟你不是模型公司，也不是专门做模型训练的。在应用层，最关键的是交互体验出色、用户体验流畅、产品定位精准。而底层涉及的很多技术，市面上都有成熟的 API，大家用的也都是那几套，并没有什么需要你从零去发明的东西。

但前提是你得知道这些 API 的存在。比如我做 TLDW 这个产品时，后端调用了一个叫 SuperData 的 API，它专门用来抓取 YouTube 的视频逐字稿。很多人不知道还有这样的工具，在评论区问我：你是怎么抓取 YouTube 逐字稿的？我说，市面上已经有非常成熟的解决方案了，你不需要自己去写，直接对接它就行。

那怎么才能知道这些新技术？就是得天天去看、去了解。所以我说，看 AI 新闻、学 AI 动态，本身就是我工作的一部分。我觉得要做好一个 AI 产品，就必须了解最新的进展。这和移动互联网时代不同——那时候的技术相对稳定，后端、前端的技术栈基本就是那些；但今天不一样，模型能力每天都在变化，每天都有新技术诞生。一旦你不再关注，就很可能在重复造轮子，做出来的东西也是徒劳。
