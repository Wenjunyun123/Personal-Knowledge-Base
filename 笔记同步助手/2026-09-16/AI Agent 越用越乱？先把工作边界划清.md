**作者：**一只桌子

烧了四十多亿 token 之后，我常驻的 Skill 只剩两个：一个是提醒我什么时候该换对话做交接，另一个把杂活丢出去替我审 token。它们看起来解决的是两个不同的问题，但指向的其实是同一件事——Agent 的工作边界。Agent 用久了之后，最容易出问题的往往不是模型能力，而是工作边界没画清楚：一个对话到底该用多久？什么时候开新项目？什么活适合丢给 Sub-Agent？什么时候需要 Worktree？这一篇把四层边界一次性讲清。

## 第一层边界：项目文件夹（固定办公室）

既然已经给 Agent 完全开放权限，它哪里都能去，那为什么还要特意建一个项目文件夹？

如果只是做一个短任务、一次性任务或者闲聊，确实没有必要。但当你真正做一系列事情或一个完整项目的时候，文件夹的重要性就出来了。打个比方：你有整栋楼的门禁卡，不代表不需要一个固定的办公室。完全访问解决的是它「能不能去」，而项目文件夹解决的是「这件长期工作有没有固定的规则和工具」。

![[笔记同步助手/images/c4916b39df6812bcd1f2c19c3a4f581a_MD5.jpg|项目文件夹作为固定办公室的示意]]

项目文件夹作为固定办公室的示意

项目文件夹最重要的意义，就是帮这段长期工作搞定两件事：

-   **沉淀项目经验。**比如我的 AGENTS.md、视频风格规范、字幕规范、采根记录，都写在项目文件夹里。换任何新对话进来，只要读一遍这些文件就能直接上手。
-   **固定工作环境。**比如我的 Remotion 工程项目级 Skill、素材处理脚本、依赖配置全在里面。下次新对话进来时面对的不是一间毛坯房，而是工具全摆在桌上，拿起就能开始干活。

## 第二层边界：对话（桌面工单）

如果项目文件夹是办公室，那对话就是今天摆在桌面上的工单。不同的事最好分开聊，这是大家都懂的；但容易忽略的一点是——同一件事也别在一个对话里拖得太长。

很多人觉得现在模型足够聪明，支持 1M 上下文都是标配，而且上下文长了 AI 会自动压缩。但实际上经常用就知道：自动压缩上下文前一两轮还行，多压几轮就压得面目全非了，后面任务出错概率直线上升。所以与其让一个对话反复压缩硬撑下去，不如及时做好交接。

![[笔记同步助手/images/a2f300454256c412f7e79e6dd6d660d0_MD5.jpg|对话越长越容易面目全非的说明]]

对话越长越容易面目全非的说明

但手动交接有两个很烦的地方：

-   我也不会一直记着「该交接了」这件事，有时候跟 AI 聊美了根本没想到这一茬，等事情开始漂移才反应过来；
-   直接换新对话，它根本不知道你前面干了什么，你又得当打字员从头交代一遍。

所以我常驻了一个交接 Skill：在需要做交接的时候主动提醒我换对话，防止我聊过头。确认交接后，它会自动帮我把「干完了什么、敲定了什么规矩、下一步从哪里开始」整理好，并自己帮我开一个新对话、发送相关指令，直接无缝接上。这样既不用当打字员，也不用操心什么时候该换对话。

## 第三层边界：Sub-Agent 思路 / 网页替身（上下文隔离）

接下来是最容易被神话的一个——Sub-Agent。很多人看到它堆得很酷炫，但现实干活中我很少会用到它。不是因为它真的不好用，主要是因为太烧 token。

不过 Sub-Agent 的思路很值得借鉴。它的核心价值其实就四个字：上下文隔离。派小弟去外面翻五万字的脏资料，把脏活杂活留在外面，最后只把提炼好的结论带回主工程。

![[笔记同步助手/images/ba9623318d770358d86f811f9de0dc87_MD5.jpg|Sub-Agent 上下文隔离思路示意]]

Sub-Agent 上下文隔离思路示意

于是我沿用 Sub-Agent 的思路做了第二个常驻 Skill，我管它叫「网页替身」。ChatGPT 网页端和 Codex 端的用量是完全分开、不共用的，而且官方客户端自带了两端的连接通道，于是我利用这个机制做了一套自动化分流：凡是遇到资料搜索、调研、常规版本分析、方案对比这种又重又吃推理的独立子任务，就自动交给网页端跑；网页端在自己的独立额度里分析与推理，跑完把精炼的结论带回来给 Codex。

这个 Skill 我主要是针对 Codex 来设计的。你如果用的是别的 AI 客户端，也可以按这个思路自己去改。

## 第四层边界：Worktree（并行沙盒）

开几个不同对话只是把任务上下文分开了。可如果这几个对话最后都去改同一个项目文件夹里的文件，还是很容易互相覆盖、互相干扰。

Worktree 相当于你给每个对话单独复制一份项目，让它们各改各的，最后把最好的结果合并回来。所以：

-   如果只是一个对话按顺序干活，完全没必要开多对话；
-   多个方案同时改同一个项目时，再用 Worktree，让每条线各跑各的。

![[笔记同步助手/images/b0ab355db768e0c4dd621de97422fad9_MD5.jpg|Worktree 给每个对话一份独立副本的示意]]

Worktree 给每个对话一份独立副本的示意

## 四层边界的完整流水线

把这四层边界放回一个完整的工作流：

1.  开一系列长期活儿时，就建项目文件夹，把规则和工具放进固定办公室；
2.  推进不同工序要交换对话；同一件事做得太久，也要及时交接；
3.  查资料、做重度分析时别硬烧主对话，按「网页替身」的思路把活派给网页端，最后只把精炼结论带回主工程；
4.  多方案并行的时候开几个 Worktree，一人一个独立沙盒，跑通了再合并。

![[笔记同步助手/images/e77a0bca2449d754f04dbca340be1d19_MD5.jpg|四层边界汇总的完整流水线]]

## 结语

Agent 用久了，真正容易出问题的往往不是模型不够强，而是所有活都往同一个地方塞。把边界画清楚，AI 才会越用越顺。

## 全文整理

烧了四十多亿 token 之后，我现在常驻的 skill 就两个：一个提醒我什么时候该换对话做交接，另一个把杂活丢出去帮我省 token。它们看起来解决的是两个不同的问题，但指向的是同一件事——Agent 的工作边界。

### 一、项目文件夹

很多新手配置 Agent 的时候会问：既然已经给了 Agent 完全开放权限，它哪里都能去，那为什么还要特意建一个项目文件夹？

它最重要的意义，就是帮这段长期工作搞定两件事。

第一件事，沉淀项目经验。比如我的 AI 视频项目里，prompt 规范、视频风格规范、字幕规范、采坑记录都写在项目文件夹里。换任何新对话进来，读一遍这些文件就能直接上手。

### 二、对话

如果说项目文件夹是办公室，那对话就是今天摆在桌面上的工单。

大家都知道，不同的活最好分开聊。但容易忽略的一点是，同一件事也别在一个对话里拖得太长。

很多人觉得现在模型足够聪明，支持一百万上下文都是标配，而且上下文长了会自动压缩。实际上经常用的人就知道，自动压缩上下文前一两轮还好，多压几轮就压得面目全非了，后面任务出错的概率直线上升。

所以与其让一个对话反复压缩硬撑下去，不如及时做好交接。

但这件事有两个很烦的地方：

一是我也不会一直想着"该交接了"这件事，有时候跟 AI 聊嗨了，根本没想到这一茬，等做事开始漂移了才反应过来。

这样既不用当打字员，也不用操心什么时候该换对话。

### 三、子 Agent

接下来是最容易被神话的一个——子 Agent。

很多人看到堆叠的子 Agent 觉得很酷炫，但在现实干活中我很少会用到它。

为什么？不是子 Agent 不好用，主要是因为太烧 token。但是子 Agent 的思路很值得借鉴。子 Agent 最核心的价值其实就四个字：上下文隔离。派小弟去外面翻五万字的资料，把脏活杂活留在外面，最后只把提炼好的结论带回主工程。

### 四、Worktree

开几个不同对话，只是把任务上下文分开了。可如果这几个对话最后都去改同一个项目文件夹里的文件，还是很容易互相覆盖、互相干扰。

### 五、把四层边界放回完整流水线

最后我们把这四个边界放回一个完整的流水线：

-   开一系列长活，就建项目文件夹，把规则和工具放进固定的办公室。
-   推进不同工序时换对话；同一件事做得太长太久了，也要及时做好交接。
-   查资料、重度分析别硬烧，子 Agent 的活派给网页端，最后只把提炼好的结论带回主工程。
