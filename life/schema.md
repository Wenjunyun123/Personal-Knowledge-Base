# 领域与字段规范

> 领域名是**定死的词表**，不是随便写的标签。同一个东西只许有一个名字，否则 AI 分析时会当成两类数据。
> 新增领域前先看这里有没有近义词。

## 一、把 JSONL 的字段说明白

每条记录一行，字段固定：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `ts` | 发生时间，`YYYY-MM-DD HH:MM` | `2026-11-25 07:20` |
| `domain` | 领域（见下表） | `体重` |
| `value` | 数值/文本原样保留 | `72.4 kg` |
| `note` | 备注，可空 | `起床后空腹` |
| `src` | 来源：`phone` / `pc` / `health` / `bill` | `phone` |

数值不做归一化——`72.4 kg` 和 `72.4kg` 都原样存，清洗交给分析时做。**保住原始记录比保住整洁重要。**

## 二、起步三件套（先只开这三个）

| 领域 | 单位/形式 | 为什么是它 | 决策用途 |
| --- | --- | --- | --- |
| **体重** | kg | 最便宜、最抗撒谎的生理指标 | 反推饮食里哪一顿是元凶 |
| **睡眠** | 小时 + 入睡时间 | 影响第二天产出质量的所有解释里，它排第一 | 判断"低效"是能力问题还是睡眠问题 |
| **情绪** | 1–10 分 | 唯一能反映"值不值得"的指标 | 长期看哪类事在消耗你 |

## 三、第二批（稳了两周再加）

| 领域 | 单位/形式 | 备注 |
| --- | --- | --- |
| 饮食 | 文本 | 只记"值得记的"和"破例的"，不记每一口 |
| 学习 | 分钟 + 内容 | 例如 `90 min 前端`，用于统计真实投入 |
| 运动 | 类型 + 分钟 | 与睡眠、情绪做相关性 |
| 消费 | 金额 + 类别 | 每周或每月从账单导入，不必手记 |
| 专注 | 分钟 + 干扰次数 | 与"睡眠"配对看，最有解释力 |

## 四、慎用（容易变成自我量化表演）

- **步数**：除非你在调整体重，否则每天一万步的数字不会改变任何决策。
- **心率变异、血糖、连续监测**：数据量大、噪声大，没有专业解读能力时只会焦虑。
- **每餐热量**：误差 20%+，统计意义低于"吃了什么"这种文本记录。

## 五、月度/周度批量源

| 来源 | 落地 | 频率 |
| --- | --- | --- |
| 支付宝 / 微信账单 CSV | `life/import/bill-YYYY-MM.csv` | 每月 |
| 健康 App 导出 | `life/import/health-YYYY-MM.json` | 每周或每月 |
| 屏幕使用时间截图 | `life/import/screen-YYYY-MM-DD.png` | 每周 |

`life/import/` 里的文件只读，`life.py` 不会改动它们，AI 直接读。

## 六、报告输出

周报写到 `life/reports/YYYY-Www.md`（例如 `2026-W48.md`）。内容由脚本生成骨架，分析结论由 AI 填。
**报告里不要出现原始记录的完整堆叠**——只保留汇总和异常，原文留在 jsonl 里可回溯。
