# 开源方案调研：多端同步 + 免费 + 可接 AI 的生活数据

> 调研日期 2026-11-25。星数、最后提交时间都是当天从 GitHub API 实读的，不是印象。
> 结论放在最前面，细节在后。

---

## 结论先说

**没有一个开源项目能同时满足「多端同步 + 免费 + 接入 AI + 覆盖生活方方面面」。** 曾经营业的那个（Nomie）已经停更。

原因是这类系统的四个需求天然分层，而开源项目全都只做**一层**：

| 层 | 需求 | 开源现状 |
| --- | --- | --- |
| 采集 | 手机上 15 秒录完 | 有，但每个 App 只管一个域 |
| 汇聚 | 一个地方存全部 | **没有**通用方案 |
| 同步 | 多端一致 | 有（Nextcloud / Git / 各自带云） |
| AI 分析 | 归因、给建议 | **几乎没有**，得自己接 |

所以"不造轮子"的现实答案是：**采集用现成 App，汇聚和 AI 用你已有的 Obsidian + Agent**。这恰好也是我已经给你搭好的那条线。

## 三、AI 层：这是缺口

**没有任何一个上面这些项目内置"给我分析、给我建议"的功能。** 它们最多给你 API 和导出。

最接近的是 Khoj，但它是**文档检索**，不是**指标统计 + 归因**。你问它"我睡得少的第二天投递数掉了多少"，它答不了——那需要按指标聚合，不是语义检索。

所以 AI 层最省事的做法不是搭 RAG，而是：**让通用 Agent 直接读文件/调 API**。

| 方式 | 项目 | 星数 | 说明 |
| --- | --- | --- | --- |
| Obsidian 通过 MCP 暴露给 AI | [mcp-obsidian](https://github.com/MarkusPfundstein/mcp-obsidian) | 4,552 | 配 Local REST API 插件，任何支持 MCP 的 AI 都能读你的库 |
| 直接读文件夹 | 不需要项目 | — | 你现在的做法：AI 有文件系统访问权，读 markdown / jsonl 就是最强的分析入口 |

## 五、两条可选路线

### 路线 A：轻（推荐，复用你已有的一切）

```
openScale(体重) ┐
Waistline(饮食) ├→ 导出 CSV/Markdown → Obsidian 库（已有同步）
Gadgetbridge(睡眠/步数) ┤                      │
Obsidian 快捷指令(情绪/学习) ┘                  ├→ Obsidian Tracker 插件画图
                                               └→ AI 读库做分析
```

- 新增成本：几个免费 App + 一个 Obsidian 插件
- 同步：**零新增**，走你现成的 GitHub
- 图表：交给你 [obsidian-tracker](https://github.com/pyrochlore/obsidian-tracker)（1,968★）插件，不用自己写
- AI：Alma / Claude 直接读文件夹，或接 mcp-obsidian

### 路线 B：重（想要真数据库 + 标准 API）

wger（身体）+ beaverhabits/Habo（习惯）+ ActivityWatch（时间）+ Memos（随手记）+ Dawarich（位置），全部 Docker 自托管，再挂 Metabase 或 Grafana 看板。

- 代价：5 个容器、5 个 App、5 套账号。手机端体验是割裂的——记体重一个 App、记情绪另一个
- 适合：你已经确定要长期做这件事，且愿意维护服务器

### 我的建议

**先走 A，别碰 B。** 你现在一条数据都没有，上 5 个容器只会得到 5 个空数据库。连续记满 3 周、有 30 条以上真实记录之后，再决定要不要给哪个域换专业工具。

---

## 六、一句话总结

- 想找"一个开源 App 全搞定"→ **不存在**，最像的那个已停更
- 想"少造轮子"→ 轮子其实只有两个：**采集 App**（用现成的）和 **AI 层**（用 Agent 读文件，别搭）
- 中间那层（汇聚 + 同步）你早就有了，就是 Obsidian + GitHub
